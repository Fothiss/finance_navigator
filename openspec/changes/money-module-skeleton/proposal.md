# Proposal

## Why

Исходная постановка модуля 1 («спред RUONIA/ROISfix к ключевой ставке — опережающий сигнал роста
ставок по кредитам МСП») неосуществима на доступных данных: ROISfix и MOSPRIME не рассчитываются
с 01.03.2022, терминальной структуры денежного рынка у ЦБ больше нет, а ставка МСП в машинном виде
доступна только с 01.2024 (~34 месяца) — на этом проверяемый сигнал не построить.

Модуль переформулируется так, чтобы сохранить исходный бизнес-вопрос («фиксировать кредит сейчас
или подождать») и сделать сигнал измеримым: два независимых индикатора стоимости денег — премия
RUSFAR1M к ключевой (MOEX) и премия кривой ОФЗ 1Y к ключевой (ЦБ) — дают вероятность повышения
ключевой ставки в ближайшие 30 дней. Ставка МСП остаётся в модуле как бенчмарк надбавки, а не как
цель прогноза.

## What Changes

- **Два независимых сигнала** с общим таргетом и общим периодом бэктеста; каждый считается отдельно,
  чтобы измерить, какой индикатор информативнее (блок `comparison` в ответе).
- **Индикаторы**: `rusfar_term_premium` = RUSFAR1M − ключевая; `ofz_curve_premium` = ОФЗ 1Y − ключевая.
  Оба приводятся к z-score по 250-дневному окну.
- **Таргет**: событие «ключевая ставка через 30 дней выше, чем сегодня» (любое повышение; ЦБ двигает
  ставку шагами от 25 б.п., поэтому повышение ≡ повышение на ≥25 б.п.).
- **Бенчмарк надбавки**: ставка по кредитам МСП (ЦБ, помесячно) − ключевая — показывает, какую надбавку
  берёт рынок; без ввода пользовательской ставки (ввод добавляется отдельным change).
- **Эндпоинты**: `GET /api/v1/money/signals`, `GET /api/v1/money/series`, `GET /api/v1/money/policies`,
  `GET /api/v1/health`.
- **Слоистая архитектура по AGENTS.md**: `routers` (валидация + вызов), `services` (индикаторы, вероятность,
  бэктест, сравнение, бенчмарк), `clients` (ЦБ SOAP + HTML КБД, MOEX ISS), `data` (кеш TTL + снапшоты),
  `config` (settings), `schemas` (Pydantic — источник типов), `models` (пусто: БД не нужна).
- **Настраиваемая политика**: пороги `p_borrow_now` / `p_wait` из UI → вердикт в сервисе; дефолт в settings;
  модельные параметры (порог z-score, окно, минимум наблюдений) в UI не отдаются.
- **Frontend-каркас** (React + Vite + TS): страница Money с двумя карточками сигналов, сравнением,
  двумя графиками и блоком бенчмарка; страницы-заглушки остальных модулей.
- **`docs/API.md`** — человекочитаемые контракты всех эндпоинтов.
- **Каркас запуска**: `docker-compose.yml`, `.env.example`; без БД и Redis (кеш в процессе).

## Capabilities

### New Capabilities

- `money-spread`: модуль «Стоимость денег» — два независимых сигнала о вероятности повышения ключевой
  ставки за 30 дней, построенных на премии денежного рынка (RUSFAR1M) и кривой ОФЗ к ключевой, с общим
  бэктестом и сравнением; плюс бенчмарк надбавки по ставкам МСП и перевод вероятности в бизнес-вердикт
  по настраиваемой политике.

### Modified Capabilities

Нет: других спецификаций в проекте ещё нет.

## Impact

- Новые каталоги: `backend/`, `frontend/`, `docs/`, плюс `docker-compose.yml`, `.env.example`.
- Внешние зависимости: API ЦБ (`DailyInfo.asmx` для ключевой; `hd_base/zcyc_params/` для КБД;
  бюллетень статистики для ставки МСП) и MOEX ISS (`history/.../RUSFAR1M.json`).
- Зависимости backend: fastapi, uvicorn, pydantic, pydantic-settings, httpx, pandas, cachetools, openpyxl
  (для xlsx-бюллетеня), pytest, ruff.
- Контракты публикуются впервые — обратной совместимости соблюдать не с чем.
- Инварианты AGENTS.md: нет точечного прогноза (вероятность + интервал), baseline рядом, сигнал без
  пройденного бэктеста не выдаётся, данные внешних систем кешируются.
